# 画面（app/）の使い方

React 18 + Vite 5 + Tailwind CSS 3。画面は 6 つ（ホーム・履歴・口座・貯金・レポート・設定）と、全画面から開ける「取引の入力」フォームです。スマホは下のタブと右下の「＋」、PC は左のサイドバーで操作します。

## 動かし方

```bash
cd app
npm install
npm test            # 画面以外のロジックのテスト（46 件）
npm run dev:demo    # デモモードで起動 → http://localhost:5173
```

- **デモモード**（`dev:demo`）：API も DB も使わず、メモリ上の仮データで全画面を操作できます。入力したデータは保存されず、再読み込みで元に戻ります。API と同じ規則（残高計算、振替、割当、「この貯金で支払う」、エラー）で動きます。
- **通常モード**（`npm run dev`）：`/api` に接続します。API とあわせた起動は Step 4（SWA CLI）で行います。

## デモモードで確認してほしいこと

初期データ：口座 4 つ（三菱UFJ銀行・現金・PayPay・楽天カード）、今月と先月の取引、貯金 2 つ（旅行・緊急資金）。

1. **ホーム**：使えるお金 ¥389,630 / 総資産 ¥519,630 / 貯金の割当合計 ¥130,000 と表示される。楽天カードの残高が赤字のマイナスになっている。
2. **出金の入力**：「＋」→ 出金 → 金額 `1200`（全角の `１，２００` でも可）・食費 → 登録。履歴に出て、ホームの口座残高が減る。
3. **振替**：種別「振替」→ 銀行から現金へ。振替元と同じ口座は選べない。履歴では「銀行 → 現金」と表示され、収支には含まれない。
4. **取引の編集・削除**：履歴の行をタップ → 金額変更、削除。残高が戻る。
5. **口座**：残高のある口座の「アーカイブ」でエラーが出る。残高を 0 にしてからアーカイブすると消える。
6. **貯金**：「割当・解除」で割当額が変わる。解除は割当額まで。「この貯金で支払う」で出金が登録され、割当が減る（履歴には「貯金から」の印が付く。その取引は金額を変更できない）。
7. **割当が総資産を超える**ように割り当てると、ホームに警告が出て、使えるお金が赤字になる。
8. **レポート**：月次（カテゴリ別の棒グラフ、振替は含まない）と年次（12 か月）。
9. **設定**：カテゴリの追加・名前変更・並べ替え（↑↓）・削除。CSV ダウンロード（Excel で文字化けしない）。

## 作りの概要

```
app/src
├─ lib/            画面に依存しない部品（テスト済み）
│   ├─ format.js        金額・日付の整形
│   ├─ validate.js      入力チェック（全角数字・カンマも受け付ける）
│   ├─ api.js           API クライアント（DB 起動中の 503 を GET だけ自動再試行）
│   ├─ client.js        本番 / デモの切り替え
│   └─ demoBackend.js   デモ用の仮バックエンド
├─ state/          共有の状態（AppContext）とデータ取得（useResource）
├─ components/     共通 UI、レイアウト、取引フォーム
└─ screens/        6 つの画面
```

- **DB が一時停止から復帰中のとき**：画面上部に「データベースを起動しています」と表示し、取得系は自動で再試行します（最大 8 回・3 秒おき）。登録・更新・削除は二重登録を避けるため自動再試行せず、エラーを表示します。
- **未ログイン・権限なし**：API が 401 / 403 を返すと、ログイン・ログアウトのリンクを表示します。
- **画面の切り替え**：`#/home`、`#/history` のようなハッシュで行うため、サーバー側の追加設定は不要です。

## 検証できていること・できていないこと

- 画面以外のロジック（`lib/`）は、単体テスト 46 件が通っています。
- 画面（`.jsx`）は、構文と、未定義の名前・存在しない import が無いことまでを確認しました。**ブラウザで表示した確認は、まだできていません**（このコードを作った環境では、パッケージのインストールとブラウザ表示ができないため）。初回の起動で見た目や動きに不具合があれば、画面とメッセージを教えてください。
