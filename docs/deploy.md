# デプロイ手順書（ローカル確認 → GitHub → Azure Static Web Apps）

> Azure の画面は更新で表記が変わることがあります。ラベルが少し違う場合は、近い項目を選んでください。
> 最新の公式情報は末尾の「参考リンク」にあります。

## 0. 全体像

```
[手元の PC]  ① ローカルで動作確認（SWA CLI）
     │
     ▼ git push
[GitHub]  ② リポジトリ kakeibo-app（Public）
     │  main への push で GitHub Actions が自動実行
     ▼
[Azure Static Web Apps (Free)]  ③ 画面 + API + 認証  ← ④ 環境変数 SQL_CONNECTION_STRING
     │                                                   ⑤ 招待で自分に owner ロール
     ▼
[Azure SQL Database]  ← 構築済み（Step 1）
```

| 順 | 作業 | 目的 | 所要時間の目安 |
| --- | --- | --- | --- |
| 1 | ローカルで動作確認 | 本番に出す前に、API と画面が DB につながって動くことを確かめる | 15 分 |
| 2 | GitHub にコードを置く | Azure が自動デプロイするための元になる | 15 分 |
| 3 | Azure で Static Web Apps を作る | 画面・API・認証の置き場を作り、GitHub と連携する | 15 分 |
| 4 | 接続文字列を登録する | 本番の API が DB につながるようにする（パスワードはコードに入れない） | 5 分 |
| 5 | 自分に owner ロールを付ける | 本人以外が使えないようにする（設計書の「本人限定アクセス」） | 10 分 |
| 6 | 動作確認 | 本番で一通り動くことと、他人が入れないことを確かめる | 15 分 |

### 作るものの名称（まとめ）

| 作るもの | 名称 |
| --- | --- |
| GitHub リポジトリ | `kakeibo-app`（**Public**） |
| Azure リソースグループ | `rg-kakeibo`（Step 1 で作成済みのものを使う） |
| Static Web Apps | `swa-kakeibo` |
| 環境変数（アプリ設定） | `SQL_CONNECTION_STRING` |
| カスタムロール | `owner` |

### 事前に必要なもの

- GitHub アカウント（2 段階認証を有効にしておくことを推奨）
- Azure のサブスクリプション（Step 1 で使用済み）
- Node.js 20 以上（Step 2・3 で導入済み）
- **Git**（手順 2 で入れます）

## 1. ローカルで動作確認（SWA CLI）

**目的：** 本番にデプロイする前に、「認証 → 画面 → API → DB」の全体が、自分の PC で動くことを確かめます。SWA CLI は、Azure 上の認証・ルーティングを PC 上で再現する道具です。

> 注意：この確認も、本番の Azure SQL につながります（設計書の方針）。確認で作ったテストデータは、最後にアプリの画面から削除してください。

### 1-1. 部品を入れる

PC のターミナル（`C:\dev\kakeibo`）で、次を順に実行します。

```
cd C:\dev\kakeibo
npm install
npm run install:all
```

- 1 つ目：SWA CLI を入れます（2〜3 分）。
- 2 つ目：`api` と `app` の部品を入れます（済んでいれば短時間）。

### 1-2. 起動

```
npm run dev
```

- 初回は、Azure Functions Core Tools（API を動かす道具）を SWA CLI が自動でダウンロードするため、数分かかることがあります。
- うまく入らない場合は、先に `winget install Microsoft.Azure.FunctionsCoreTools` を実行してから、もう一度 `npm run dev` を実行します。
- `http://localhost:4280` と表示されたら起動完了です。

### 1-3. ログイン（エミュレーター）

1. ブラウザで **`http://localhost:4280`**（5173 ではありません）を開きます。5173 は認証を通らない画面だけの確認用です。
2. ログイン画面（本物の GitHub ではなく、SWA CLI の疑似ログイン）が出ます。
3. ユーザー名は何でもよく、**ロール欄に `owner`** と入力して、ログインします。
   - ロールを空にすると、本番と同じく 403 になります（これで認可の動きも確かめられます）。

### 1-4. 確認すること

- [ ] ホームに口座・使えるお金が表示される（DB のデータ）。
- [ ] 最初のアクセスで少し待たされることがある（DB が一時停止から復帰中。画面上部に「データベースを起動しています」が出て、自動で表示される）。
- [ ] 「＋」から出金を 1 件登録 → 履歴に出て、ホームの残高が変わる。
- [ ] 登録したテスト取引を、履歴から削除する。

終了は、ターミナルで `Ctrl + C` です。

## 2. GitHub にコードを置く

**目的：** Azure は、GitHub の `main` ブランチを見て、push のたびに自動でビルド・公開します。

> **このリポジトリは Public（誰でも見られる）で公開します。** 公開してよい内容（ソースコードと手順書）だけを置き、**パスワード・接続文字列・サーバー名・ログイン名などの識別情報は一切入れません**（本物の値は、Azure の環境変数と、GitHub に上がらない `api/local.settings.json` にだけ置きます）。コード内の例は、すべて `<サーバー名>` のようなプレースホルダーに置き換えてあります。

### 2-0. 公開前の準備：DB の管理者パスワードを強くする（推奨）

**目的：** コードを公開すると、「どんな仕組みか」は誰にでも分かります。DB のパスワードが破られにくければ安全なので、公開前に、**長くて推測されにくいパスワード**に変えます。

1. Azure ポータルで、SQL サーバー（`sql-kakeibo-〇〇`）を開き、「概要」から **「パスワードのリセット」**（表記は多少違うことがあります）を選びます。
2. 新しいパスワードを決めます。
   - **24 文字以上**、英大文字・小文字・数字を混ぜる。
   - 記号は **`-` `_` `.` `!` `#` だけ**にする（`"` `\` `;` `'` `=` 空白 `<` `>` は、設定ファイルの書き方で問題になるので使わない）。
   - 名前・誕生日・他のサービスと同じものは使わない。パスワード管理アプリで作ると簡単です。
3. 保存したら、手元の `api/local.settings.json` の `Password=` の部分を、新しいパスワードに書き換えて保存します。
4. 手順 1 の `npm run dev` で、DB につながることを確認します（つながらなければ、パスワードの書き間違いです）。
5. 手順 4 の「環境変数」には、**必ず新しいパスワード**を登録します。

### 2-1. Git を入れる

1. <https://git-scm.com/download/win> から Git for Windows をダウンロードして入れます（設定は初期値のままで構いません）。
2. 入れたあと、VS Code とターミナルを **いったん閉じて開き直し**、`git --version` を実行して、バージョンが表示されることを確認します。
3. 名前とメールを登録します（GitHub に登録したメールアドレス）。

```
git config --global user.name "あなたの名前"
git config --global user.email "GitHubに登録したメール"
```

### 2-2. GitHub に空のリポジトリを作る

1. <https://github.com/new> を開きます。
2. Repository name：**`kakeibo-app`**
3. **Public** を選びます。
4. 「Add a README file」「.gitignore」「license」は**すべてオフ**のままにします（空のリポジトリにする）。
5. 「Create repository」を押します。

> ライセンスを付けない場合、他の人はコードを自由に使えません（著作権は自分に残ります）。コードを使ってもらいたいときだけ、あとから `LICENSE`（MIT など）を追加してください。付けなくても、アプリの動作には影響しません。

### 2-3. コミットして push する

```
cd C:\dev\kakeibo
git init -b main
git add .
```

**ここで必ず確認します。** パスワードを含むファイルが入っていないことを確かめます。次の 2 つを、**1 行ずつ**実行してください（複数行をまとめて貼り付けると、表示が崩れて読み間違えやすくなります）。

```
git ls-files api/local.settings.json
```

- **何も表示されなければ OK** です（ファイル名をそのまま指定しているので、`.example` と見間違えることがありません）。
- `api/local.settings.json` と表示されたら **NG**（Git の対象に入っています）。**push も commit もせずに**止まって、教えてください。

```
git check-ignore -v api/local.settings.json
```

- `.gitignore:7:api/local.settings.json ...` のように、**どの行で無視されているか**が表示されれば OK です。

次に、`node_modules` などが入っていないことを、ファイル数で確認します。

```
(git ls-files).Count
```

- 100〜150 くらいなら OK です。**数千以上**なら `node_modules` まで入っているので、止まって教えてください。

**公開前の最終確認（Public なので、必ず行います）。** 次の 2 つを実行して、表示される行が**すべてプレースホルダー**（`<サーバー名>`、`<パスワード>`、`example-server` など）であることを確認します。

```
git grep -nI "windows.net"
git grep -nIi "password="
```

- 本物のサーバー名・ログイン名・パスワードが 1 行でも出たら、**push せずに**止まって、教えてください。
- 一度 push した内容は、あとから消しても履歴に残り、誰でも見られます。**push の前が最後のチェックです。**

問題なければ、続けます。

```
git commit -m "初回コミット"
git remote add origin https://github.com/あなたのGitHubユーザー名/kakeibo-app.git
git push -u origin main
```

- 初回の push で、ブラウザが開いて GitHub へのサインインを求められます。許可してください。
- 成功したら、GitHub のリポジトリの画面を更新して、ファイルが並んでいることを確認します。
- 「Actions」タブに、`Tests` というワークフローが走ります（テストと画面のビルド確認）。緑のチェックになれば OK です。**ここで画面のビルド（`npm run build`）が初めて実際に実行されます。** 赤い × になったら、ログの内容を教えてください。

## 3. Azure で Static Web Apps を作る

**目的：** 画面（静的ファイル）・API（マネージド Functions）・認証を、1 つのリソースで公開します。GitHub と連携すると、Azure が **自動デプロイ用のワークフローを GitHub に追加**してくれます。

> **入力の書き方：** この手順書の中の `バッククォートで囲んだ文字`（例：`/app`、`dist`）は、**読みやすくするための印**です。入力するときは、`` ` `` を**付けずに**、中の文字だけを入力してください（例：`/app` と入力）。

> **前提：** この手順の前に、手順 2 で GitHub に `kakeibo-app` を push しておきます（画面でリポジトリとブランチを選ぶため）。

1. [Azure ポータル](https://portal.azure.com) の上部検索欄に「**Static Web Apps**」（日本語表記では「静的 Web アプリ」）と入力して開き、「**作成**」を押します。作成画面には、**基本 → デプロイ構成 → 詳細設定 → タグ → 確認および作成** の 5 つのタブがあります。

2. **「基本」タブ**（画面を下へスクロールすると、続きがあります）

| 項目 | 入力する値 |
| --- | --- |
| サブスクリプション | 使っているもの |
| リソース グループ | **`rg-kakeibo`**（既存を選ぶ） |
| 名前 | **`swa-kakeibo`** |
| プランの種類 | **Free** |
| デプロイの詳細：ソース | **GitHub** |

   「GitHub でサインイン」を押して許可し、続けて次を選びます。

| 項目 | 入力する値 |
| --- | --- |
| 組織 | 自分のユーザー名 |
| リポジトリ | **`kakeibo-app`** |
| ブランチ | **`main`** |

   「ビルドの詳細」は次のとおりです（**ここを間違えると、ビルドが失敗します**）。

| 項目 | 入力する値 |
| --- | --- |
| ビルドのプリセット | **Custom** |
| アプリの場所 | **`/app`** |
| API の場所 | **`/api`** |
| 出力先 | **`dist`** |

3. **「デプロイ構成」タブ**

| 項目 | 選ぶもの |
| --- | --- |
| デプロイ認可ポリシー | **デプロイ トークン**（初期値のまま。公式でも推奨） |

   - 「デプロイ トークン」：Azure が発行したトークンを、GitHub の「シークレット」に保存し、GitHub Actions がそれを使ってデプロイします（手順 3-1 のワークフローは、この方式の書き方です）。
   - 「GitHub」にすると、ワークフローの書き方が変わり、この手順書の確認項目と合わなくなります。**変えないでください。**

4. **「詳細設定」タブ**

| 項目 | 入力する値 |
| --- | --- |
| Azure Functions API とステージング環境のリージョン | **East Asia**（選択肢に日本のリージョンがあれば、DB と同じ Japan East でも可） |
| エンタープライズ レベルのエッジ | **オフ**（チェックしない。Standard プラン（有料）が必要なため） |

   - このリージョンは、**API（マネージド Functions）が動く場所**を決めます。画面（静的ファイル）は、世界中のエッジから配信されるため、影響しません。

5. 「**タグ**」タブは、そのままで構いません。「**確認および作成**」タブで内容を確認し、「作成」を押します。
6. 完了したら「リソースに移動」を押し、概要の **URL**（`https://……azurestaticapps.net`）を控えます。

### 3-1. 自動デプロイの確認

- 作成の直後に、Azure が GitHub のリポジトリへワークフローのファイル（`.github/workflows/azure-static-web-apps-〇〇.yml`）を追加し、最初のデプロイが自動で始まります。
- GitHub のリポジトリの「Actions」タブで、**「Azure Static Web Apps CI/CD」が緑のチェック**になるまで待ちます（3〜5 分）。
- 追加されたファイルを、手元に取り込みます。

```
cd C:\dev\kakeibo
git pull
```

- 取り込んだファイルの `with:` の中が、次の値になっていることを確認します（`〇〇` は Azure が決めた名前で、人によって違います）。

```yaml
          azure_static_web_apps_api_token: ${{ secrets.AZURE_STATIC_WEB_APPS_API_TOKEN_〇〇 }}
          repo_token: ${{ secrets.GITHUB_TOKEN }}
          action: "upload"
          app_location: "/app"
          api_location: "/api"
          output_location: "dist"
```

> 以後は、**`main` に push するたびに、自動でデプロイ**されます。このファイルは Azure が管理するので、手で書き換えないでください。

## 4. 接続文字列を登録する（アプリ設定）

**目的：** 本番の API が DB につながるための情報を、Azure 側に安全に置きます。**ソースコードや GitHub には、パスワードを入れません。**

1. ポータルで `swa-kakeibo` を開きます。
2. 左メニューの「設定」の中の **「環境変数」** を選びます。
3. 環境は **Production**（本番）を選びます。
4. 「**＋ 追加**」を押し、次を入力します。

| 項目 | 入力する値 |
| --- | --- |
| 名前 | `SQL_CONNECTION_STRING` |
| 値 | 下の接続文字列（**前後に `"` を付けない**） |

```
Server=tcp:<サーバー名>.database.windows.net,1433;Database=kakeibo;User Id=<管理者ログイン>;Password=<パスワード>;Encrypt=true;
```

- ここは JSON ファイルではないので、**`"` で囲みません**。`local.settings.json` とは書き方が違います。
- `ここにパスワード` を、実際のパスワードに置き換えます（`<` `>` も付けない）。
- `local.settings.json` に書いたものと**同じ値**で構いません。

5. 「OK」→「**保存**」（または「適用」）を押します。

## 5. 自分に owner ロールを付ける（招待）

**目的：** 設計書の「本人限定アクセス」です。`staticwebapp.config.json` が、全画面と全 API を `owner` ロールの人だけに限定しているため、**自分に `owner` を付けないと、自分も入れません**（ログイン後に 403 になります）。

1. ポータルで `swa-kakeibo` を開き、左メニューの「設定」の中の **「ロール管理」** を選びます。
2. 「**招待**」を押し、次を入力します。

| 項目 | 入力する値 |
| --- | --- |
| 承認プロバイダー | **GitHub** |
| 招待の詳細 | **自分の GitHub ユーザー名**（メールではなくユーザー名） |
| ドメイン | 一覧にある `swa-kakeibo` の URL |
| ロール | **`owner`** |
| 招待の有効期間（時間） | `24`（最大 168） |

3. 「生成」を押し、表示された **招待リンクをコピー**します。
4. 新しいブラウザタブで、**そのリンクを開きます**。GitHub へのサインインを求められるので、**手順 2 で入力したユーザー名のアカウント**でサインインします。
5. サインインが終わると、`owner` ロールが付与されます。

> - 招待リンクは、他人に渡さないでください（第三者が使うと、その人に権限が付きます）。使い終わったら、ロール管理の一覧に自分が `owner` で表示されていることを確認します。
> - 違うアカウントで受けてしまったら、ロール管理でそのユーザーを削除してから、招待をやり直します。
> - 設計書どおり、使わないログイン方法（Microsoft アカウント・X）は `staticwebapp.config.json` で 404 にして、塞いでいます。**GitHub を塞ぐと招待を受けられなくなる**ので、塞がないでください。

## 6. 動作確認

### 6-1. 本番の画面（自分）

- [ ] 控えた URL を開く → GitHub のログインに移る → 戻ってきて、ホームが表示される。
- [ ] 最初のアクセスで、「データベースを起動しています」が出て、しばらく待つと表示される（DB が一時停止から復帰中。1 分ほどかかることがあります）。
- [ ] 出金・振替を 1 件ずつ登録し、履歴と残高に反映される。
- [ ] 貯金の割当、「この貯金で支払う」が動く。
- [ ] 設定 → CSV ダウンロードで、Excel で文字化けせずに開ける。
- [ ] **確認で作ったテストデータを、画面から削除する。**

### 6-2. 他人が入れないこと

- [ ] 普段と別のブラウザ（またはシークレットウィンドウ）で、同じ URL を開く → GitHub のログインに移る（ログインしていない人は入れない）。
- [ ] そのブラウザで `https://〇〇/api/summary` を開く → ログインに移るか、エラーになる（データは見えない）。
- [ ] ログアウトは、`https://〇〇/.auth/logout` で行えます（設定画面の「ログアウト」でも可）。

### 6-3. スマホ

- [ ] スマホのブラウザで URL を開き、ログインして使える。
- [ ] 「ホーム画面に追加」しておくと、アプリのように起動できます。

## 7. 以後の運用

| やりたいこと | 方法 |
| --- | --- |
| 画面や API を直す | 手元で修正 → `git add .` → `git commit -m "内容"` → `git push` → 数分で自動デプロイ |
| デプロイの状況を見る | GitHub の「Actions」タブ |
| 失敗した変更を戻す | `git revert` してから push |
| 接続文字列・パスワードを変える | ポータルの「環境変数」で値を更新（SQL サーバーのパスワードを変えたときも、ここを更新） |
| 費用が心配 | ポータルの「コストの管理」→「予算」で、小さな金額（例：数百円）のアラートを作っておく |
| DB の無料枠 | 月の無料枠を使い切ると、翌月まで DB が自動で一時停止します（追加料金は発生しません） |

### 守ってほしいこと（Public リポジトリ）

- `api/local.settings.json` を GitHub に上げない（`.gitignore` 済み）。**push の前に、毎回** `git status` で、変更に秘密情報が含まれていないか確認する。
- 手順書やコードに、**本物のサーバー名・ログイン名・パスワードを書かない**。Issue やプルリクエストの本文、スクリーンショットにも載せない。
- **もし秘密情報を push してしまったら**：ファイルを消すだけでは足りません（履歴に残るため）。**すぐに DB の管理者パスワードを変更**し（手順 2-0）、「環境変数」と `local.settings.json` を更新します。その後、相談してください。
- パスワードをチャットや画面共有に出さない。
- GitHub アカウントは 2 段階認証にする（このアカウントが、アプリへの入口になります）。
- 他人からのプルリクエストは、内容を確認するまでマージしない。

## 8. うまくいかないとき

| 症状 | 考えられる原因と対処 |
| --- | --- |
| GitHub の Actions が赤い × | 「Actions」→ 失敗した実行 → 赤い手順のログを開く。**アプリの場所 `/app`、API の場所 `/api`、出力先 `dist`** が正しいか確認（手順 3-1 の値）。ログの該当部分を教えてもらえれば原因を調べます。 |
| サイトを開くと 404 | 出力先が `dist` でない／画面のビルドが失敗している。Actions のログを確認。 |
| ログインしても 403 | `owner` ロールが付いていない。手順 5 の招待を、**正しい GitHub アカウント**で受け直す。ロール管理の一覧を確認。 |
| ログインを何度も求められる | ブラウザの Cookie が無効、または別アカウントでログインしている。`/.auth/logout` でログアウトしてから、やり直す。 |
| 画面は出るが「ログインが必要です」 | 画面のあとで、セッションが切れた。再読み込みして、ログインし直す。 |
| `/api/…` が 404 | API がデプロイされていない。Actions のログで、API のビルドが成功しているか確認（API の場所が `/api` か）。 |
| API が 500（「内部エラー」） | 環境変数 `SQL_CONNECTION_STRING` が未登録、または値が違う（`"` を付けていないか、パスワードの誤り）。手順 4 を見直す。 |
| 「データベースを起動中です」が長く続く | DB の一時停止からの復帰待ち。1〜2 分待つ。続くなら、SQL サーバーの「ネットワーク」で「Azure サービスおよびリソースにこのサーバーへのアクセスを許可する」が有効か確認（Step 1 で設定済み）。月の無料枠を使い切っていないかも確認。 |

### エラーの「詳細コード」の見方

画面のエラー表示の下に「詳細コード：〇〇」と出ます。`https://（サイトのURL）/api/summary` をブラウザで開いても、JSON の `detail` に同じコードが出ます（パスワードやサーバー名は含まれません）。

| 詳細コード | 意味 | 対処 |
| --- | --- | --- |
| `40613` | DB が一時停止中、または起動中 | 1〜2 分待って再読み込み。DB の「状態」を確認（SQL データベース `kakeibo` の「概要」） |
| `40501` / `49918` / `49919` / `49920` / `10928` / `10929` | Azure 側が混み合っている／無料枠の制限 | 少し待つ。続くなら、無料枠を使い切っていないか確認 |
| `ETIMEOUT` / `ESOCKET`（`ENOTFOUND` なし） | 接続がタイムアウト・切断された | 少し待って再試行。続くなら、SQL サーバーの「ネットワーク」で、Azure サービスのアクセス許可が有効か確認 |
| `ESOCKET/ENOTFOUND` | **サーバー名が違う**（接続先が見つからない） | 環境変数 `SQL_CONNECTION_STRING` の `Server=tcp:…database.windows.net,1433;` を、SQL サーバーの「サーバー名」と一字一句そろえる（`<` `>` や前後の `"` を付けない） |
| `ESOCKET/ECONNREFUSED` | 接続先に拒否された | `Server=` のポート（`,1433`）を確認 |
| `ELOGIN/18456` | **ログイン名またはパスワードが違う** | 環境変数の `User Id=` と `Password=` を確認（パスワードを変更したなら、ここも更新） |
| `ELOGIN/40615` | SQL サーバーのファイアウォールで拒否された | SQL サーバー →「ネットワーク」→「Azure サービスおよびリソースにこのサーバーへのアクセスを許可する」を有効にする |
| `ELOGIN/4060` | **DB 名が違う** | 環境変数の `Database=kakeibo` を確認 |
| コードなし（500） | 接続文字列が未登録、または形式が不正 | 手順 4 を見直す（環境変数の名前は `SQL_CONNECTION_STRING`） |
| 最初のアクセスだけ遅い／504 になる | DB が停止中だったため。SWA の API は 1 リクエスト最大 45 秒までで、超えると 504 になりますが、画面が自動で再試行します（API の処理は裏で続いており、再試行すればつながります）。 |
| `npm run dev`（ローカル）で `func` が見つからない | `winget install Microsoft.Azure.FunctionsCoreTools` で入れてから、ターミナルを開き直す。 |
| ローカルで DB につながらない（`Cannot open server`） | PC の IP アドレスが変わった。Azure の SQL サーバー →「ネットワーク」で「クライアント IP アドレスを追加」→ 保存。 |
