# Azure SQL Database（無料オファー）セットアップ手順

開発・本番ともに Azure SQL Database を直接使う構成です（ローカル DB・Docker は使いません）。

## 0. 注意点（本番直結のため）

- 開発中のテストデータも本番 DB に入ります。動作確認が終わったら、アプリの画面から削除するか、`DELETE` で消してから本格運用に入ってください。
- 無料枠（月 100,000 vCore 秒）を超えると、翌月まで DB が自動一時停止します。個人の開発規模なら通常は収まります。
- DB は無操作が続くと自動一時停止し、次のアクセスで数十秒〜1 分かけて復帰します（API 側のリトライで吸収する設計です）。

## 1. データベースを作成する

1. Azure ポータルで「SQL Database」を作成します。
2. 「Azure SQL Database 無料オファーを適用する」を選びます。
3. 「**無料上限に達したときの動作**」は必ず「**翌月まで自動一時停止**」にします（「追加料金で継続」は選ばない）。
4. SQL サーバーを新規作成します。認証方法は「SQL 認証」を選び、管理者ログインとパスワードを控えておきます。
5. 無料オファーの条件は変わることがあるため、作成前に公式ドキュメントで最新条件を確認してください。

## 2. ネットワーク（ファイアウォール）設定

SQL サーバー →「ネットワーク」で次を設定します。

| 設定 | 目的 |
| --- | --- |
| 「Azure サービスおよびリソースにこのサーバーへのアクセスを許可する」を有効 | 本番の SWA マネージド Functions から接続するため |
| 「クライアント IP アドレスを追加」 | 手元の PC から `schema.sql` の実行や、ローカルでの API 起動を行うため |

自宅の IP アドレスが変わると手元から接続できなくなります。その場合は同じ画面で IP を追加し直してください。

## 3. スキーマと初期データを適用する

`db/schema.sql` → `db/seed.sql` の順に、**作成した DB に対して**実行します。

- **VS Code の「SQL Server (mssql)」拡張機能、または Azure Data Studio**（推奨）：DB に接続し、2 つのファイルを順に開いて実行します。`GO` 区切りも正しく処理されます。
- **sqlcmd**：
  ```bash
  sqlcmd -S <サーバー名>.database.windows.net -d <DB名> -U <管理者> -P <パスワード> -f 65001 -i db/schema.sql
  sqlcmd -S <サーバー名>.database.windows.net -d <DB名> -U <管理者> -P <パスワード> -f 65001 -i db/seed.sql
  ```
- ポータルの「クエリ エディター」は `GO` を扱えない場合があります。使う場合は、`CREATE VIEW` を単独で実行してください（ビューはバッチの先頭である必要があります）。

`schema.sql` は初回専用です（再実行するとテーブルが既に存在するというエラーになります）。`seed.sql` は何度実行しても重複しません。

## 4. 動作確認

```sql
SELECT COUNT(*) AS category_count FROM categories;  -- 17
SELECT * FROM v_account_balances;                   -- 0 行（口座はアプリから登録）
```

## 5. 接続文字列

環境変数 `SQL_CONNECTION_STRING` に次の形式で設定します。

```
Server=tcp:<サーバー名>.database.windows.net,1433;Database=<DB名>;User Id=<管理者>;Password=<パスワード>;Encrypt=true;
```

- **ローカル実行**：`api/local.settings.json` の `Values` に設定します（`.gitignore` 済みなので Git には入りません）。
- **本番**：SWA の「環境変数（アプリ設定）」に登録します（Step 4 で手順化します）。
- パスワードをソースコードやリポジトリに含めないでください。
